# 휴대폰 감지 재현율(0.38) 개선 방안 비교

현재 출시 설정은 640×480 입력, EfficientDet-Lite0 int8 전체 프레임 탐지, 판정 기준 0.5, 20초 연속 + 3초 히스테리시스입니다.
COCO 사진 기준 성능은 정밀도 1.00, 재현율 0.38(34/90), 오탐 0/150입니다(`frontend/bench/vision/RESULTS.md` §A).

**표기 규칙**
- **실측**: W1 벤치마크에서 실제로 돌린 값. Apple Silicon 데스크톱, 메인 스레드, CPU(XNNPACK) 기준.
- **추정**: 계산이나 공개 자료로 낸 값. 실측 전에는 결정 근거로 쓰지 않습니다.
- CPU 비용 단위는 "ms/s"입니다. 1초 동안 추론에 쓰는 시간이며, 얼굴·자세는 2Hz, 물체 탐지는 1Hz로 셉니다.

**현재 기준값(실측)**: 93.7 ms/s, 모델 wasm 메모리 약 149MB.

## 2. 저사양 영향
- 탐지기 비용이 3배가 되면 저사양 기기에서는 적응형 감속(adaptive cadence)이 더 일찍 걸립니다.
- 그러면 얼굴·자세 주기도 같이 느려집니다. 시간 기준 자체는 경과 시간이라 바뀌지 않고, 전환이 늦어질 뿐입니다.
- 5배 느린 기기라면 Lite2 탐지만으로 초당 약 720ms가 듭니다(추정 = 144.8ms × 5). 이 정도면 기본값으로 켜기 어렵습니다.
- 1번 방안이 "선택형"이어야 하는 이유이자, 4번 방안(단계형)을 검토하는 이유입니다.

## 3. 권장 순서
1. **현장 기준선 먼저.** `docs/webcam-eval.md`의 휴대폰 구간으로 실제 웹캠 재현율을 잽니다.
   - 휴대폰 위치 3종 × 조명 3종 × 3회를 측정합니다.
   - COCO는 작은 휴대폰이 많아 웹캠보다 비관적인 수치일 수 있습니다. 현장 수치가 충분하면 모델 변경이 필요 없을 수도 있습니다.
2. **Lite2 선택형 모드 검증.** 같은 현장 프로토콜과 CPU 4배·8배 제한에서 Lite2의 재현율, 오의심, 추론 p95, 저전력 진입 여부를 잽니다.
   - 실측 효과가 가장 확실하고 구현이 가장 쉽습니다.
   - 기본값은 Lite0을 유지하고, 사용자가 켜는 방식(동의 문구에 CPU 사용 증가 안내)으로 합니다.
3. **단계형(4번) 측정.** 2번의 CPU 비용이 문제일 때만 진행합니다.
   - 후보 기준(예: Lite0 점수 0.2–0.5 또는 사람 상자 안 손 위치)에서 Lite2가 실행되는 비율 f를 현장 음성 데이터로 잽니다.
   - 같은 데이터로 재현율도 잽니다.
4. **장기: 웹캠 도메인 재학습(7번).** 학생 동의를 받은 데이터만 쓰고, 브라우저 안에서 라벨링하는 절차를 먼저 설계합니다.
   - 원본 영상의 서버 저장 금지 원칙과 충돌하지 않게 하는 것이 전제입니다.
   - 이 단계는 별도 승인이 필요합니다.

6번(기준값 낮추기)은 단독으로는 하지 않습니다. 7번이나 실제 영상 음성 데이터가 생겼을 때 함께 검증합니다.
8번은 라이선스와 Safari 지원을 먼저 확인합니다.

이 문서는 비교 자료일 뿐이며 **아무 변경도 출시하지 않았습니다**.
