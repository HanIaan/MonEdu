# 실제 Safari 수동 테스트 체크리스트 (우선순위별)

Playwright WebKit 자동 테스트는 **Safari가 아닙니다.** WebKit 엔진만 같고, Safari 앱의 다음 동작은 재현하지 않습니다.
- 전력 절약
- 자동재생 정책
- 탭 일시정지
- 카메라 권한 UI
- macOS 카메라 표시등

아래 항목은 사용자가 실제 Safari.app과 실제 웹캠으로 직접 확인해야 합니다.

**우선순위**
- **P0**: 막히면 Safari를 지원한다고 말할 수 없음
- **P1**: Safari 고유 정책 때문에 집계가 틀릴 수 있음
- **P2**: 정확도·장시간 안정성

## 준비
- macOS Safari. 버전은 Safari ▸ Safari에 관하여에서 확인해 기록합니다.
- 서버: 프론트 http://localhost:3000, 백엔드 8080.
  현재 3000번은 진단 훅이 켜진 프로덕션 빌드라서 콘솔에서 `__smDiag.snapshot()`을 쓸 수 있습니다.
- 진단 페이지: `cd tests/e2e/fixtures && python3 -m http.server 4800` → http://localhost:4800/video-visibility-probe.html
- 계정: 학생 `student3@demo.local`, 선생님 `teacher2@demo.local`(비밀번호 `demo1234!`).
  자동 테스트가 쓰는 student1, student2, soak 계정은 쓰지 마세요. 세션이 서로 교체됩니다.
- 선생님 화면은 다른 브라우저(Chrome 등)나 다른 기기에서 엽니다.
- (선택) 콘솔 사용: Safari ▸ 설정 ▸ 고급 ▸ "웹 개발자용 기능 보기"를 켠 뒤 개발 ▸ JavaScript 콘솔을 엽니다.

화면 용어는 다음과 같습니다.

| 구분 | 화면에 보이는 이름 |
|---|---|
| 상태 배지 | `집중 추정`, `비집중 의심`, `자리비움`, `측정 불가`, `휴식` |
| 카드 정보 | "카메라"(작동 중 / 권한 거부 / 중단됨), "AI 모델"(준비됨), "분석 속도"(fps), "p95 추론 시간" |
| 측정 불가 이유 | 카드의 측정 불가 이유 문구 |

## P0 — 기본 동작
| # | 절차 | 예상 결과 | 실패 시 의미 | 결과 |
|---|---|---|---|---|
| P0-1 | 진단 페이지 → "실제 카메라로 측정" → 권한 허용 | 6개 방식 모두 "프레임 공급됨". 특히 첫 줄 `analysis-host (2×2px…)` | 첫 줄이 실패하면 미리보기를 닫았을 때 분석이 멈춤. 표 전체와 User-Agent를 캡처해 공유 | ☐ |
| P0-2 | student3 로그인 → 동의 체크 → ‘학습 시작’ → 권한 허용 | 10–30초 안에 카메라 "작동 중", AI 모델 "준비됨", 분석 속도가 0보다 큼(빠른 맥에서 약 2fps) | 모델 로드나 워커가 Safari에서 실패. 측정 불가 이유 문구를 기록 | ☐ |
| P0-3 | **미리보기를 닫은 채** 정면에 앉아 30초 | 모델 준비 후 약 15–20초 뒤 `집중 추정`. 분석 속도 유지 | 숨겨진 video에 프레임이 오지 않음(P0-1과 함께 확인) | ☐ |
| P0-4 | 자리를 비우고 45초 → 돌아와 30초 | 나간 뒤 약 30–35초에 `자리비움`, 돌아온 뒤 약 15–20초에 `집중 추정` | 상태 기계 시간 기준 오류 | ☐ |
| P0-5 | ‘모니터링 중단’ → 20초 → ‘모니터링 재개’ | 중단: 맥 카메라 초록 표시등 꺼짐, `측정 불가`, 문구 "모니터링이 일시 중단되어 측정하지 않습니다.", 집중 시간 증가 멈춤. 재개: 표시등 켜짐, 15–25초 안에 `집중 추정` | 카메라 자원 해제 실패(개인정보 문제) | ☐ |
| P0-6 | 새 개인정보 보호 창에서 student3 → 학습 시작 → 권한 **허용 안 함** | 카메라 "권한 거부", 문구 "카메라 권한이 거부되어 측정할 수 없습니다.", 집중 0초 | 권한 거부가 다른 오류로 보임 | ☐ |

## P1 — Safari 고유 정책과 집계 공정성
| # | 절차 | 예상 결과 | 확인 방법 | 결과 |
|---|---|---|---|---|
| P1-1 | 학습 중 다른 탭으로 전환 → 2분 → 복귀 | 둘 중 하나여야 합니다. (a) 계속 측정, (b) 약 5초 뒤 `측정 불가` + "분석이 지연되어 측정할 수 없습니다.". **(b)이면 숨겨진 동안 집중 시간이 늘면 안 됨.** 복귀 후 15–20초 안에 `집중 추정` | 전환 전·후 "오늘 총 집중 추정" 값을 메모해 비교. 선생님 타임라인의 회색 빗금(측정 불가) 구간 확인. (a)/(b) 중 어느 쪽인지 기록 | ☐ |
| P1-2 | Safari 창 최소화 → 2분 → 복귀 | P1-1과 같음 | 같음 | ☐ |
| P1-3 | 맥 화면 잠금 → 2분 → 해제 | 잠금 동안 집중 시간 증가 없음. 90초를 넘기면 선생님 화면 `측정 불가`. 해제 후 다시 3초 확인을 거쳐 `집중 추정` | 집중 시간 비교, 선생님 화면 | ☐ |
| P1-4 | 학생 맥의 Wi-Fi 끄기 → 2분 → 켜기 | 끈 뒤 약 60–100초에 선생님 화면 `측정 불가`(heartbeat 90초 기준). 켜면 30초 안에 학생 상태가 복귀하고 대기 이벤트가 전송됨. **끊긴 구간은 측정 불가로 남고 집중으로 바뀌지 않음** | 선생님 학생 상세 타임라인에서 끊긴 구간이 회색 빗금(측정 불가)인지 | ☐ |
| P1-5 | 착석·자리비움·복귀(P0-4)를 하는 동안 선생님 화면 관찰 | 학생 화면에서 상태가 바뀐 뒤 약 1–3초 안에 선생님 화면도 바뀜 | 두 화면을 나란히 놓고 관찰 | ☐ |
| P1-6 | ‘미리보기 확인’으로 열었다 닫기를 3번 반복 | 상태와 분석 속도 유지, `측정 불가` 없음 | 분석 속도 값 | ☐ |
| P1-7 | Safari를 다른 앱 창 뒤에 두고(창은 보이는 상태) 2분 | 계속 측정, 상태 유지 | 분석 속도 값 | ☐ |

## P2 — 정확도와 장시간
행동 시나리오는 `docs/webcam-eval.md`의 프로토콜을 Safari에서 사람이 진행하며 기록합니다. 아래는 그 요약입니다.

| # | 절차 | 예상 결과 | 결과 |
|---|---|---|---|
| P2-1 | 고개를 숙여 필기 75초(어깨는 화면 안) | `집중 추정` 유지, **`자리비움`이 되면 안 됨** | ☐ |
| P2-2 | 책 읽기 75초 | `집중 추정` 유지 | ☐ |
| P2-3 | 휴대폰을 카메라에 보이게 들고 60초 | 약 20–35초 뒤 `비집중 의심`. 사진 기준 재현율이 0.38이라 실패할 수 있음. 실패하면 휴대폰 위치를 기록 | ☐ |
| P2-4 | 휴대폰을 치우고 40초 | 약 15–20초 뒤 `집중 추정` | ☐ |
| P2-5 | 책상에 엎드리기 60초 | **판정 규칙 없음(수면 감지 미출시).** 실제로 나온 상태를 기록 | ☐ |
| P2-6 | 30분 이상 실행. 활성 상태 보기(Activity Monitor) ▸ 에너지 탭과 메모리 탭에서 Safari 웹 콘텐츠 프로세스를 관찰 | 메모리가 계속 늘지 않음. 분석 속도 유지. 에너지 영향 값 기록 | ☐ |
| P2-7 | (선택) 콘솔에서 `__smDiag.snapshot().perf` 실행 | `p95InferenceMs`, `lowPower`, `framesDropped` 값 기록 | ☐ |
